## Data minimization and exposure findings

- The workflow needs contact details and a property-specific layout for sales follow-up, but the
  current consent text does not disclose Resend/ServiceM8 forwarding, processor location, or
  indefinite retention.
- `additionalInfo` is optional and should remain optional because it can collect unexpected
  sensitive information.
- Raw provider payloads and credentials are excluded by the persisted schema, which is a positive
  minimization control.
- The current design has no implemented access/correction, archive/delete, retention expiry, or
  breach-scoping workflow. Real customer data must not be used while that development-only gate
  remains.

## NZ Privacy Act 2020 code-verifiable scope

- IPP1/2: partly met; the individual directly supplies data for a pool enquiry.
- IPP3/4: incomplete; notice omits processors, forwarding, retention, access/correction, and
  deletion behavior.
- IPP5: blocked for release; development access is contained, but database at-rest encryption,
  production authorization, audit coverage, and artifact leakage evidence are not established.
- IPP6/7: fail for a customer-ready release; no access or correction path exists.
- IPP8: fail for report integrity while client-supplied evidence and consent facts are trusted.
- IPP9: fail; no retention period or deletion path exists.
- IPP10/11: blocked; intended use is documented, but disclosure notice and enforceable limitation
  evidence are incomplete.
- IPP12: blocked; overseas processor/storage locations and comparable safeguards are not recorded.
- IPP13: partly met; the product creates an assessment reference for its own purpose and does not
  reuse another agency's identifier as identity.
